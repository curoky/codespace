# macOS 开发环境

- 工具环境缺失时加载 `~/.zshrc`；项目工具链覆盖在加载后设置。
- Python 环境与项目依赖使用 uv，按需用 `--python` 选择
  `~/.local/share/uv/python` 中的版本。
- Node.js 优先使用 26；按项目需求从 `~/.local/share/node/nodejs*` 选择版本，将其 `bin`
  放到 PATH 首位。
- Node.js 全局 CLI 位于 `~/.local/share/node/tools`，不使用全局 npm 或 pnpm 安装。
- Go runtime 位于 `~/.local/share/go`，用户安装的 Go 命令位于 `~/go/bin`。
- standalone tools 由 `platform/macos/binman.yaml` 声明并安装到 `~/.local`；Homebrew 软件
  由 `platform/macos/Brewfile` 声明。
- 缺少系统软件、全局 CLI 或 runtime 时，说明用途并使用
  `.agents/skills/manage-macos-environment` 中对应的 maintenance 操作，不执行未声明的临时安装。

# AI 协作准则

## 工程原则

- 简单优先且面向长期：选择能完整满足当前需求的最简实现，避免投机性的抽象、配置与间接层；同时做面向长期的架构决策，不接受注定日后被替换的权宜之计。
- 不要过度配置化以及过度提取常量。
- 不保留向后兼容性。移除过时的路径，而非添加兼容层、回退（fallback）或迁移逻辑。
- 分层演进系统。从能端到端跑通的最小版本起步，在已可运行的产品之上叠加每一项新能力。绝不用一个可运行的产品去换取未完成的复杂度。
- 保持组件模块化，关注点清晰分离。
- 依赖优先级：先善用项目中已有的依赖，再考虑引入成熟且维护良好的库降低复杂度或提升可靠性，最后才自行实现；不重复造轮子，也不在未查阅文档与类型定义前臆断某个库缺少某项能力。
- 现代技术优先。始终采用每种语言官方最新稳定且生态兼容的语法、功能、工具链与依赖；先核实版本状态，再锁定。
- 识别出一次性任务（如数据迁移、配置改造），用不入 Git 仓库的一次性代码完成。

## 协作与产物约定

- 交互沟通默认用中文。写文档时中英混合，描述性主体用中文，标题、专用名词与业界通用概念保留英文，保证准确与可检索。
- 用给 AI 看的 AGENTS.md 替代给人看的 README.md，及时更新关键上下文；过大时按主题拆到同目录专题文档（如 `DESIGN.md`）并在 AGENTS.md 保留索引。
